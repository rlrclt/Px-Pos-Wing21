1.1 รูปแบบการทำงาน SPA & การจำข้อมูลข้ามหน้า (Zero-Reload Architecture)

ทำไมเวลาเปลี่ยนหน้าจอ (เช่น สลับจาก POS ไปดูรายงาน แล้วกลับมา) ข้อมูลถึงไม่ต้องโหลดใหม่ และของในตะกร้าไม่หาย?

Single Page Application (SPA)
แบบเดิม (Multi-Page App / MPA)

โหลดใหม่ทั้งหน้าทุกครั้งที่กดเปลี่ยนลิงก์

  • หน้าจอดำ/กะพริบ (Page Refresh): เบราว์เซอร์ต้องยิงขอ HTML+JS ใหม่ทุกหน้า ทำให้ช้า 1-3 วินาที
  • ข้อมูลที่พิมพ์ค้างไว้หาย: ตะกร้าสินค้าที่ยิงไว้หลุด ต้องเริ่มยิงสินค้าใหม่
  • ดึง Database ซ้ำซ้อน: เปลืองเน็ตและติด Quota ของ Google Sheets อย่างรวดเร็ว
ระบบ PX กองบิน 21 (Modern SPA + State Cache)

เปลี่ยนหน้าไว 0 วินาที & เก็บข้อมูลในหน่วยความจำถาวร

  • Client-Side Routing (React Router): โหลดหน้าเว็บครั้งแรกครั้งเดียว การสลับหน้าเป็นการสลับ Component ภายใน RAM (0.001s ไร้การกะพริบ)
  • In-Memory State (Zustand Store): ตะกร้าสินค้า, ทหารที่เลือกไว้, กะแคชเชียร์ คงอยู่ตลอดเวลา แม้สลับไปหน้า Admin แล้วกลับมา
  • Persistent Local Database (Dexie IndexedDB): สินค้า 10,000 ชิ้นและคิวออฟไลน์เก็บลงเครื่อง ไม่ต้องดึงเน็ตซ้ำ
1. Virtual DOM Swap
สลับหน้าใน RAM

เบราว์เซอร์ไม่ Refresh หน้า สลับ View ด้วย JavaScript ในเสี้ยววินาที

2. Reactive Store
Zustand State Cache

State ตะกร้า, ยอดเงิน, กะแคชเชียร์ ฝังอยู่ใน Store ส่วนกลาง ไม่ถูกลบ

3. IndexedDB Cache
เก็บ Catalog ถาวร

เปิดเครื่องปุ๊บ ค้นหาสินค้าจากเครื่องตัวเองทันที < 5ms ไม่ต้องรอเน็ต

4. Smart ETag Sync
อัปเดตเฉพาะเมื่อมีแก้

ดึงข้อมูลจาก Sheets เฉพาะเมื่อมีการเปลี่ยนราคาสินค้าหรือเพิ่มรายการใหม่

3. การเชื่อมต่ออุปกรณ์ฮาร์ดแวร์หน้าร้าน (POS Peripherals)

เทคนิคการคุยกับเครื่องสแกนบาร์โค้ด เครื่องพิมพ์ใบเสร็จ และลิ้นชักเก็บเงิน

เครื่องยิงบาร์โค้ด (Scanner)

รองรับเครื่องสแกน USB / Bluetooth ทุกรุ่นในโหมด Keyboard Wedge (HID)

// ดักจับ Keypress ต่อเนื่อง (< 50ms interval)
window.addEventListener('keydown', handleGlobalBarcodeScan);
เครื่องพิมพ์สลิป (ESC/POS)

พิมพ์ผ่าน Web Bluetooth หรือ Print Dialog แบบ Silent Printing

// คำสั่ง ESC/POS ตัดกระดาษ
const CUT_PAPER = new Uint8Array([0x1D, 0x56, 0x41, 0x00]);
ลิ้นชักเก็บเงิน (Cash Drawer)

ต่อสาย RJ11 เข้ากับเครื่องพิมพ์ สั่งเด้งอัตโนมัติเมื่อรับเงินสด

// คำสั่ง Kick Drawer RJ11
const OPEN_DRAWER = new Uint8Array([0x1B, 0x70, 0x00, 0x19, 0xFA]);

4. ความปลอดภัยและการซ่อนราคาทุน (Security & Cost Shield)

หลักการปกป้องข้อมูลทางการค้าและสิทธิ์การเข้าถึง (RBAC)

ซ่อนราคาทุนจากหน้าจอแคชเชียร์ 100%

หน้าจอ POS แคชเชียร์จะดาวน์โหลดเฉพาะตาราง Product_Catalog (ไม่มีคอลัมน์ราคาทุนและ GP) แคชเชียร์จึงไม่มีทางเห็นกำไรหรือต้นทุนของจ่า ส่วนการบันทึก cost_price_at_sale จะถูกจัดการฝั่ง Server บน Google Apps Script เท่านั้น

Void Authorization Gate

การกดยกเลิกบิลหรือคืนเงิน (Void / Refund) แคชเชียร์ไม่สามารถทำได้โดยพลการ ระบบจะบังคับให้กรอก PIN หรือสแกนบัตรของระดับ ADMIN เพื่ออนุมัติ พร้อมบันทึก authorized_by ลงใน Void_Logs เสมอ
